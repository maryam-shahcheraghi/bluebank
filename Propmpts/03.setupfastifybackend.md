# Set Up a Minimal Fastify Backend

## Original User Prompt

Act as a senior NestJS and Turborepo engineer. Set up a minimal, production-oriented NestJS backend inside an existing empty Turborepo.

Implement the setup, run the relevant checks, and verify that the application starts successfully. Keep the scope limited to configuration, bootstrap code, and a health endpoint.

Before implementation:
- Read applicable AGENTS.md files and the Turborepo skill available in this repository.
- Inspect the root package.json, packageManager field, lockfile, workspace configuration, and turbo.json.
- Use the existing package manager and repository conventions. Do not introduce a second package manager or lockfile.
- Preserve existing configuration and unrelated changes.
- Consult current official documentation for compatible NestJS, Fastify, and SWC configuration.
- Ask targeted questions if a requirement is ambiguous or existing configuration conflicts with this request. Resolve routine implementation details yourself.

Application:
- Create the backend in apps/api.
- Use NestJS with @nestjs/platform-fastify.
- Do not use Express, Express middleware, or @nestjs/platform-express as a direct application dependency.
- Use the Fastify-native equivalents if any adapter-specific configuration is necessary.
- Do not add frontend applications in this task.

Bootstrap:
- Create the application using:
  NestFactory.create<NestFastifyApplication>(
    AppModule,
    new FastifyAdapter(...)
  )
- Call app.enableShutdownHooks().
- Make the listening port configurable through PORT, defaulting to 4000.
- Validate the port and handle bootstrap failures with a nonzero exit status.
- Configure the listening host explicitly and document the local and container behavior.

Compiler and TypeScript:
- Use the Nest CLI SWC builder for development and production compilation.
- Enable TypeScript strict mode.
- Set experimentalDecorators: true.
- Set emitDecoratorMetadata: true.
- Ensure SWC actually supports and emits the legacy decorators and decorator metadata required by NestJS. TypeScript compiler flags alone are insufficient for SWC output.
- Use compatible module settings for the chosen NestJS runtime.
- Add an independent typecheck script using TypeScript with --noEmit.
- Ensure production validation includes type checking because SWC transpilation alone does not verify types.
- Reuse an existing shared TypeScript configuration if appropriate without inheriting incompatible frontend settings.

Health endpoint:
- Add GET /health.
- Return HTTP 200 with a minimal JSON body:
  { "status": "ok" }
- Keep it lightweight; no external services or database checks.
- Do not add a health-check framework unless it is actually necessary.

Turborepo integration:
- Provide application scripts for dev, build, start:prod, typecheck, and lint where supported.
- Integrate them into the root commands and existing turbo.json task graph.
- Configure dev as persistent and non-cacheable.
- Declare correct build outputs for the actual NestJS output directory.
- Ensure production execution uses compiled JavaScript.
- Do not overwrite the existing task graph or unrelated scripts.
- Do not introduce dependencies on persistent development tasks.

Scope:
- No database, ORM, authentication, login, authorization, queues, or business features.
- No unnecessary shared packages, Docker configuration, or deployment infrastructure.
- Include only dependencies and scaffolding needed for this backend.
- Add a safe .env.example and document exactly how configuration is loaded.
- Ignore real environment files and generated artifacts.

Verification:
1. Install dependencies with the existing package manager.
2. Run type checking and applicable lint checks.
3. Build through the root Turborepo command.
4. Start development mode and verify GET /health.
5. Start the compiled production application and verify GET /health again.
6. Stop the processes you started.

Fix failures before finishing. Never report a check as successful unless you executed it successfully. If a check is blocked, state the exact limitation.

- Files and configuration changed.
- Commands to develop, typecheck, build, and run production.
- The health endpoint URL.
